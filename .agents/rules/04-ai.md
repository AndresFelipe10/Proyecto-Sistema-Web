# Regla 04 — Módulo de IA

**Nivel de aplicación:** siempre que se trabaje dentro de `app/AI/` o `app/Services/AI/`, o se modifique el flujo de consultas en lenguaje natural.

Arquitectura completa, flujo y ejemplos → `docs/MODULO_IA.md`

## Restricciones NO negociables (aplicar en código, nunca solo en el prompt al modelo)
- La IA NUNCA tiene acceso directo a MySQL, credenciales, ni ejecuta SQL generado por el modelo.
- La IA solo puede devolver una intención perteneciente a una whitelist explícita en código (enum/registro). Cualquier intención fuera de esa lista se rechaza, aunque el modelo la "invente".
- Cada intent tiene su propio Service de solo lectura (`get()`, `first()`, `count()`, agregaciones). Prohibido usar `save()`, `update()`, `delete()` dentro de cualquier servicio invocado desde el módulo IA.
- El `business_id` usado en cada consulta de IA es siempre inyectado por Laravel desde el usuario autenticado — nunca proporcionado por el modelo ni tomado de texto libre del usuario.
- Prohibido enviar al proveedor externo contraseñas, hashes, tokens, o volcados de datos reales de negocio. Solo se envía la pregunta, el esquema de intents permitidos y metadatos mínimos.
- El sistema depende de `AiProviderInterface`, nunca directamente del SDK de Gemini, en ningún punto fuera de `app/AI/Providers/GeminiProvider.php`.
- El módulo debe poder desactivarse por completo vía flag en `.env` sin romper ningún otro módulo. Verificar esto tras cualquier cambio relevante al módulo IA.

## Fallback obligatorio
Ante timeout, error o cuota agotada del proveedor: mensaje controlado al usuario, nunca error técnico visible. Ejemplo de mensaje ya aprobado en `docs/MODULO_IA.md`.
